# Guide For Us

Purpose of this guide: Explains how we organise work, code, and keep the project organised overall.

## 1. Before starting work 
1. Check GitHub task board for tasks.
2. Select an issue
3. Read the issue description
4. Move issue to in progress once you begin

   Avoid working on tasks that are **In Progress** without discussing it first

   Alternatively you can create new tasks for yourself. Make sure to put it in the board though!




## 2. Working on tasks
* Work on a clearly defined task one at a time wherever possible
* Keep work within relevant project files
* Encounter a problem? Document it in the relevant issue, you can also mention it in your development log entry.
* If a task turns out to be larger than expected, split it into multiple issues.
* Ask before making major changes to project structure.


## 3. Using GitHub
1. Save changes
2. Commit changes with a descriptive message.
3. Push changes to GitHub
4. Update the relevant Issue.
5. Move the issue to **Done** once the task is GENUINELY complete.


## 4. Project Organisation
> Report/ -> Offline website and its assets

> Artefact/ -> Game, hardware, data analysis. 


## 5. Communication
* Task related discussions in GitHub issues where possible.
* Tell the group if you're having issues. Don't be a bum.
* Discuss major design decisions before implementation.
* Keep project board updated so everyone knows what is happening and where we're at.


## 6. Documentation and Evidence

Throughout development:
* Take screenshots of significant progress, put it into the [google drive](https://drive.google.com/drive/folders/1NU1wtfgBbh4rkQoUDD6eLlJXOtqzfUP6?usp=sharing) where possible.
* Record important design decisions in [development](development.md).
* Document bugs and how they were fixed in [development](development.md).
* Photograph hardware its prototypes and testing.
* Keep track of research sources. Easiest way to do this is if you search something up put it inside of [resources](https://github.com/accountforcomputerscience/alt4-2project/issues/1#issue-6254167814)


## 7. SUPER DUPER DUPER IMPORTANT SECTION
Everyone should understand the overall project. BE prepared to explain the code, decisions and testing during the interview.

If you're unsure about something ask. Speak the evil, even make us frustrated if it means you can understand.
